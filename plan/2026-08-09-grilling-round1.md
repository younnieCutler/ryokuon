# ryokuon — Local-First 양방향 녹음 툴 (grilling 진행 중)

## 환경 (확인됨)
- macOS 26.6 (Darwin 25.6), M3 Pro, Xcode 26.4 / Swift 6.3
- 프로젝트 dir: `/Users/macbook/dev/tools/ryokuon` — 비어있음, git 아님
- `Speech.framework`: `SpeechAnalyzer`/`SpeechTranscriber`/`SpeechDetector`(VAD)/`AssetInventory` 존재
- ffmpeg 설치됨, BlackHole 등 가상 오디오 드라이버 불필요

## 원 요구사항
- 이어폰/마이크(ME) vs Mac 내부 상대방(REMOTE) 분리 녹음
- STT 인식 가능 수준 음질 (고음질 아님)
- 트랙별 음량 조절, 비파괴
- 권한 설정 후 원클릭 시작/종료
- 녹음·전사·저장 Local-First
- 로컬 STT로 ME/REMOTE 구분 전사
- 동일 화자 연속 발화 병합, 불필요 데이터 제거
- compact transcript: `타임스탬프|M|R|텍스트`
- AI가 전체 transcript 대신 필요한 발화만 조회
- 우선순위: 안정성 > STT 인식 음질 > Local-First/보안 > 저CPU/저용량 > 토큰 최소화

## 확정된 결정 (Round 1 + Round 2)

**Q1 화면 구성** — 메뉴바(시작/끝) + 창 하나(녹음 목록, 재생기, 전사 읽기, 목소리 크기 슬라이더). **저장 경로 지정 가능하게** (사용자 추가 요청).

**Q2 상대방 목소리 녹음 방식** — 맥 스피커로 나가는 소리를 앱이 바로 가져가는 방식(권한 처음 한 번만).

**Q3 녹음 파일 음질** — 전화 통화 수준. 1시간당 약 115MB, 전사 후 자동 절반 압축.

**Q4 음량 조절 범위** — 실시간 모니터링 조절은 없음. 목적은 "AI(STT)가 목소리를 제대로 들을 수 있는 수준"의 볼륨 보정. 나중에 다시 들을 때 + STT 돌릴 때 쓸 볼륨값만 저장, 원본 파일은 안 건드림.

**Q5 음성인식 엔진** — 애플 자체 음성인식(Speech.framework) 먼저 사용. 안 되면 그때 외부 엔진 검토.

**Q6 상대방이 여러 명일 때** — 사람별 구분 없이 전부 "상대방(R)"으로 처리.

**Q7 언어** — **일본어가 메인 언어**, 한국어·영어도 지원. 기본값은 일본어.

**Q8 AI가 대화 내용 찾아볼 때** — 터미널 명령어로 검색 (`ryokuon search 회의1 "배포"` 형태), 필요한 부분만 출력.

---

**Q9 저장 위치** — 기본 폴더는 `~/Documents/ryokuon/`. 앱 창에서 "저장 폴더 바꾸기" 버튼으로 언제든 변경 가능.
→ 응 확정

**Q10 세션 이름** — 자동으로 날짜+시간 붙고(`2026-08-09_1430`), 나중에 목록 창에서 이름 바꿀 수 있게.
→ 응 확정

**Q11 정전/강제종료 대비** — 녹음 중간에 죽어도 그때까지 녹음분은 살아야 함(안정성 최우선). 파일을 계속 조금씩 디스크에 써둠.
→ 응 확정

**Q12 발화 합치기 기준** — 같은 사람이 2초 이상 조용하면 새 발화로 구분.
→ 응 확정

**Q13 불필요한 데이터 제거** — 무음 구간만 자동 제거. 필러("어", "음" 등)는 남겨두고 신뢰도 낮은 구간은 지우지 말고 표시만 해두기.
→ えっと、えー、へー 같은 질질끄는 말들은 검색해봐서 지울지 말지 판단해줘.

**Q14 권한 요청** — 순서대로 하나씩(마이크 → 오디오캡처 → 저장폴더). 각 화면에서 "왜 필요한지" 한 줄 설명 후 시스템 권한 팝업.
→ 응 확정

**Q15 전사 시점** — 녹음 끝나고 일괄 처리. 실시간 자막은 CPU 낭비라 나중에.
→ 응 확정

**Q16 보관 기간 / 암호화** — 앱이 따로 암호화 안 함(FileVault로 충분). 자동 삭제 없음(사용자가 직접 관리).
→ 응 확정

---

**Q17 상대방 트랙에 딴 소리 섞임** — "맥에서 나가는 소리 전부"를 가져오면 알림음·유튜브·음악까지 녹음돼서 전사됨. 이어폰 안 끼면 스피커 소리를 마이크가 되받아서 상대 말이 내 트랙에도 중복으로 들어감.

→ **앱 골라서 녹음** 확정. 녹음 시작 전 "어느 앱 소리를 녹음할지" 목록에서 선택(Zoom, Slack, 크롬 등). 알림음·음악 안 섞임.
- 원클릭 유지 방법: 마지막 선택 앱 기억 → 메뉴바에 `녹음 시작 — Zoom`으로 떠서 한 클릭. 앱 변경할 때만 목록 열림.
- 남는 한계: 브라우저로 회의하면 같은 브라우저의 유튜브 소리도 같이 잡힘.

**Q18 녹음 실패 감지** — 가장 흔한 사고가 "마이크 음소거된 줄 모르고 1시간 무음 녹음".

→ **소리 막대 + 무음 경고** 확정. 녹음 중 트랙별 소리 크기를 실시간 막대로 표시. 한 트랙이 30초 넘게 아무 신호 없으면 알림.
- 경고 조건은 "녹음 시작 후 한 번도 신호가 없었던 트랙"만. "신호 있다가 끊김"은 통화 중 침묵과 구분이 안 돼서 제외.

## 추가 결정 (사용자 코멘트 반영)

**Q13 보충 — 일본어 필러(えっと、えー、あの、まあ) 처리**
→ 조사 결과 및 결정은 아래 "필러 처리 결정" 절 참고.

**전사본 포맷 상세** — 확정
- 타임스탬프: 밀리초 정수, 발화 시작 시각
- 형식: `12400|M|金曜日までにデプロイします。`
- 저신뢰 구간(평균 신뢰도 0.5 미만): 텍스트 앞에 `?` — `31050|M|?聞き取りにくかった部分`

**UI 스타일** — Pinterest / Mobbin 레퍼런스 참고, 편한 스타일. 구현 시 별도 확인.
