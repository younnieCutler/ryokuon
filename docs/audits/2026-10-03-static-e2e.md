## Findings, highest severity first

| Severity | Baseline evidence | Failure path | Change |
| --- | --- | --- | --- |
| P1 | `Sources/Ryokuon/RingBuffer.swift:59-71` | Drain clears count and unlocks before copying the same storage the producer can overwrite; wraparound can corrupt the consumer snapshot. | Swap two preallocated buffers under the lock; copy the owned snapshot outside it. Count overwritten unread samples correctly. |
| P1 | `Sources/Ryokuon/AudioCapture.swift:140-157` | Each mic channel is appended to the same ring sequentially. Stereo mic input produces twice as many mic samples as tap samples, stretching/misaligning the two tracks. The interleaved path also allocates on the audio callback. | Average the selected channels per frame for planar and interleaved buffers, without temporary sample arrays. |
| P1 | `Sources/Ryokuon/Session.swift:110-119`; `Sources/Ryokuon/AppState.swift:503-519` | Concurrent imports or import plus recording can both pass the existence check for the same timestamp directory, sharing metadata/audio paths. | UUID-suffixed directory identity; retain readable timestamp display names; serialize GUI import batches. |
| P1 | `Sources/Ryokuon/Session.swift:170-177,213-215` | The decoded ID is trusted as a path, although the folder should be authoritative. Edited metadata can redirect later reads or recursive deletion. Invalid channel counts can also trap during recovery conversion to UInt16. | Validate folder/metadata identity, channel count, finite metadata; constrain deletion to an immediate child. This is not a general defense against hostile filesystem symlink races. |
| P1 | `Sources/Ryokuon/AppState.swift:344-378,503-519` | Storage root changes and deletions are allowed while background workers still hold old directories. New imports can then be transcribed against another root; active work can lose its directory. | Guard root changes across recording/import/transcription/export, track export ownership, block active-session deletion, remove deleted queued work, stop playback on deletion/root change. |
| P1 | `Sources/Ryokuon/AudioImporter.swift:59,73-79`; `Sources/Ryokuon/FLACConverter.swift:38-40,64` | Decoder errors are treated as EOF; short FLAC output only needs to be nonempty before the original WAV is removed. | Propagate read/conversion failures and reject empty imports; stage FLAC, check frame count/rate/channels, publish before deleting WAV. |
| P1 | `Sources/Ryokuon/Session.swift:154`; `Sources/Ryokuon/AppState.swift:330-338,361-372,476-480` | Nonatomic metadata writes risk a truncated JSON file; `try?` still updates UI after failure; mutations of stale Session copies overwrite newer fields. | Atomic JSON writes, fresh read-modify-write, UI publication only after success, localized error reporting. Recovery only reports successful repair+save. |
| P2 | `Sources/Ryokuon/Views.swift:200,327,341` | Single-row/menu deletion is immediate and permanent; only multi-selection confirms. | Route both through confirmation; disable active-session delete controls; backend guards remain authoritative. |
| P2 | `Sources/Ryokuon/MP3Exporter.swift:29-35,43-44`; `Sources/Ryokuon/Views.swift:1152-1158` | Encoder writes directly over an existing export; invalid positions reach integer conversions; the sheet dismisses even on failure. | Stage and validate encoded output, publish with replacement, validate bounds, retain failed export sheet with error/retry controls, prevent dismissal during export. |
| P2 | `Sources/Ryokuon/Player.swift:89,133-144`; `Sources/Ryokuon/AppState.swift:278-297` | Selecting default output does not reset the audio unit. Seeking beyond EOF returns success although playback never starts; previous UI playback state survives a failed replacement. | Resolve and apply actual default device, check OSStatus, reject invalid seeks, clear AppState playback before attempting a replacement. |
| P2 | `Sources/Ryokuon/CaptureDevice.swift:38-52`; `Sources/Ryokuon/AudioCapture.swift:163-166,210-236` | Partial capture setup can leak a tap/IOProc; writer errors are logged but stop can claim success; cleanup is skipped if finish throws. Mic switch failures can leave a timer with no running IOProc. | Failure cleanup, final resource teardown, retain/surface first write error, drain before changing sample rate, stop/finalize failed mic switches and restore the selected preference. |
| P2 | `Sources/Ryokuon/AppState.swift:433` | Synchronous FLAC conversion runs inside the inherited main-actor task and can block the UI for long recordings. | Move conversion to a detached worker while maintaining the session operation guard. |

## Regression coverage added — not executed

- SessionStore: concurrent creators, rejected redirected IDs/invalid channels, unsuccessful recovery remaining retryable, deletion errors.
- AppState: isolated-store injection, stale metadata edits preserving other fields, failed persistence not publishing a successful rename.
- RingBuffer: overflow accounting, repeated drains, concurrent producer/consumer order. Run the concurrency test with Thread Sanitizer as well.
- AudioTrackMixer: stereo microphone + mono tap, both planar and interleaved; output frame alignment and mixed sample values.

- FLACConverter: full frame count across a chunk boundary; failed empty conversion preserves original WAV and existing FLAC.
- MP3Exporter: invalid range preserves an existing export; existing range-encoding test remains.

These tests cover deterministic boundaries, not every hardware/fault path in the table. Encoder crashes, disk-full during capture, live device switches, write permission errors during atomic replacement, operation interleavings through the GUI and native accessibility still require macOS checks.

## Remaining limitations / follow-up risks

- All modified Swift, including new APIs and concurrency behavior, still needs compilation on the target SDK. This is a static audit, not a passed E2E audit or a release approval.
- Player and transcription still decode whole files into memory; very long recordings need memory/performance profiling and potentially streaming implementations (`Player.swift:56-61`, `Transcriber.swift:156-168` in the baseline).
- WAV uses UInt32 byte counters and RIFF lengths; recordings approaching 4 GiB still need a deliberate rotation/limit strategy (`WAVWriter.swift:24,46,74`).
- Permission flags remain cached, speech auto-detection uses confidence heuristics, silence warnings remain Korean-only, and application termination during active work is not redesigned.
- MP3+Markdown is not one atomic multi-file transaction: a successful MP3 can remain if the later Markdown write fails. Each individual completed export is protected from a failed encoder; batch rollback is not implemented.
- Invalid/unreadable session metadata is excluded from the sidebar; a dedicated damaged-session recovery UI is not included.
- No release, installer execution, main-branch push, deployment, or real-recording migration is part of this work.
