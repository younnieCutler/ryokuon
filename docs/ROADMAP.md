# Toward 1,000 stars

Stars are a discovery outcome, not an acceptance criterion. The product must first earn repeated use and independent recommendations.

## Positioning

A native, local meeting notebook for people who want searchable recordings without a subscription or handing business audio to a SaaS. Developers get inspectable files, a CLI and reproducible distribution; office users get explicit capture, readable transcripts, useful notes and export.

## Launch gates

1. Finish the measured hardware acceptance and first notarized release.
2. Record an actual 60-second demo: capture → bookmark → transcript search → meeting notes → Markdown export.
3. Publish EN/JA/KO quick starts and explain mono fallback, remote-channel speaker limits and mixed-language limitations plainly.
4. Invite 10–20 testers with diverse microphones and call apps. Fix their repeatable recording/install failures before broad promotion.
5. Share the working release with Swift/macOS and privacy-focused communities. Follow community rules; show the actual app and invite technical criticism.

## Next work driven by evidence

- Pause/resume and 0.75–2× playback after capture and playback hardware regression coverage exists.
- Cancellable transcription with model-download progress and explicit resume/retry controls.
- User-selected export folder, transcript correction and subtitles after tests for timestamp/format contracts.
- Large-library search indexing only when measured rebuild time justifies incremental persistence.
- Alternate local recognition engines only if users need older macOS or additional languages; preserve the default local processing contract.

Track successful first recordings, repeat usage and reproducible issue counts through opt-in tester feedback. Do not add telemetry merely to count adoption. Avoid claims about guaranteed accuracy, perfect speaker separation or a guaranteed star count.
